# 設計書・セキュリティレビュー

実装前に確認するための設計案です。決定事項が変わったらこのファイルを更新してください。

## 1. 全体構成

```
[スマホ / PC のブラウザ]
      │  ① 画面（HTML/CSS/JS）
      ▼
[GitHub Pages]  ……  site/ フォルダ。公開されて困る情報は置かない
      │
      │  ② API 呼び出し（ログイン・一覧・アップロード）
      ▼
[Cloudflare Worker]  ……  worker/ フォルダ。認証と権限チェックはすべてここ
      │
      │  ③ R2 バインディング（キー不要）
      ▼
[Cloudflare R2：cocc-video-site]  ……  非公開バケット
```

- 画面は GitHub Pages、処理は Worker、保存は R2。
- Worker からは R2 を「バインディング」で操作するので、R2 のアクセスキーを発行・保管する必要がない。

## 2. 主要な設計判断（要確認）

### 2-1. ログイン状態の持ち方：トークン方式
- GitHub Pages（github.io）と Worker（workers.dev）は別ドメインのため、iPhone の Safari では Cookie が使えない。
- そのため、ログイン成功時に Worker が署名付きトークンを発行し、ブラウザは保存して API 呼び出し時に `Authorization` ヘッダーで送る。
- 閲覧者：有効期限 7 日、`localStorage` に保存（毎回パスワードを入れなくてよい）。
- 管理者：有効期限 2 時間、`sessionStorage` に保存（タブを閉じるとログアウト）。
- トークンの中身は「種類（viewer / admin）＋有効期限」で、`TOKEN_SECRET` による HMAC-SHA256 署名付き。中身を書き換えると署名が合わず拒否される。
- 将来、独自ドメインを用意した場合は HttpOnly Cookie 方式に切り替え可能。

### 2-2. 動画の再生・保存：Worker 発行の署名付き URL
- Worker が「期限付き（10 分）・改ざん不可」の URL を発行し、その URL へのアクセスだけ Worker が R2 から動画を返す。
- R2 の URL は外に出ない。シークバー用の Range リクエストにも対応する。
- 保存ボタンは同じ URL に `download` 指定を付けて端末へ保存させる。

### 2-3. アップロード：Worker 経由の分割アップロード
- Worker が受け取れる 1 回のサイズに上限（無料プランは 100MB）があるため、50MB ずつ分割して送る。
- サムネイルは管理者のブラウザで動画の 1 コマを画像化し、動画と一緒に保存する（サーバー側の変換処理なし）。

### 2-4. チーム・フォルダの管理
- R2 内の `_config/settings.json` にチーム一覧とフォルダ一覧を保存する。
- 管理画面から追加・変更でき、コード修正は不要。

### 2-5. R2 内の保存場所
```
_config/settings.json
videos/<フォルダ名>/<チーム名(任意)>/<動画ファイル名>
thumbs/<フォルダ名>/<チーム名(任意)>/<動画ファイル名>.jpg
```

## 3. セキュリティレビュー

| 想定される脆弱性 | リスク | 対策 |
|---|---|---|
| フロントの変数を書き換えて管理者になる | 不正アップロード・削除 | 権限はトークンの署名で Worker が毎回確認。フロントの判定は表示切替のみ |
| パスワードの総当たり | 不正ログイン | Worker の Rate Limiting で 1 分 5 回まで。失敗はログに記録（パスワードは記録しない） |
| パスワード・秘密鍵の流出 | 全権限の奪取 | Worker Secret で管理し Git に入れない。Push protection でも検知 |
| 動画 URL の転送・流出 | 部外者の閲覧 | 署名付き URL は 10 分で失効。R2 は非公開 |
| 不正ファイルのアップロード | 容量圧迫・悪用 | 拡張子・MIME・ファイル先頭のバイト列で mp4/mov のみ許可。上限サイズを設定 |
| XSS（トークン盗難） | なりすまし | 画面の表示は `textContent` のみ使用し `innerHTML` を使わない。CSP を meta タグで設定。外部スクリプト不使用 |
| 他サイトからの API 呼び出し | 不正操作 | CORS を GitHub Pages のドメインのみに限定 |
| 他プロジェクトへの影響 | 誤削除 | Worker は専用、R2 バインディングは cocc-video-site のみ |

## 4. 秘密情報（Worker Secret）

| 名前 | 内容 |
|---|---|
| `VIEWER_PASSWORD` | 閲覧用パスワード |
| `ADMIN_PASSWORD` | 管理者用パスワード |
| `TOKEN_SECRET` | トークン・署名付き URL の署名鍵（ランダムな長い文字列） |

## 5. 実装の順番（ブランチ）

1. `feature/setup`：雛形・設計書（このブランチ）
2. `feature/auth`：ログイン（閲覧者・管理者）
3. `feature/viewer`：チーム選択・一覧・モーダル再生・保存
4. `feature/admin`：アップロード・フォルダ／チーム管理
5. 運用マニュアル・デプロイ手順の仕上げ
